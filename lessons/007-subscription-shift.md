# 007: サブスク転換 — 最適化変数は同じ、単位と時計が変わった(USD/月 → 週次枠/週)

**2026-07-20(Fable 5)・2026-09-01(Fable 5.1)以降、MaxプランではFableが週次枠の50%まで追加費用なしで使える。型の「Fableだけ従量」という前提は消えたが、最適化変数「Fableのトークンを何に使うか」は不変。変わったのは単位(USD→枠負荷)と時計(月次予算→週次リセット+5時間枠)。従量(クレジット)は50%上限到達後に任意で選んだ時だけ発生する。**

状態: **v1.1採用**(2026-09-12)。根拠=公式ヘルプ「Claude Fable models on your plan」(support.claude.com/en/articles/15424964)+2026-07-20発表(X @claudeai)。型への反映=model-routing.md v1.1改訂点・orch skill §3/§4(A)/§6/§7/§8/§8b・agent_usage.py・降板ガード文言。

## 事実(2026-09-12時点)
- Max/Team Premium/Enterprise Premium: Fable 5・5.1が週次枠の**最大50%まで追加費用なし**。Pro/標準シート: 最初からクレジット(API単価 $10/$50)。
- 50%は**同一週次枠の内側の上限**で上乗せではない。Fableを使うとOpus/Sonnetの残量も減る。逆に週次枠全体が先に尽きることもある。
- Fableは枠に対し**Opusのおよそ2倍の重み**(公式倍率は未公表。単価比と整合)。Fable 5.1はFable 5比で1ターンの出力が約2倍との観測報告があり、枠を「分で溶かす」事例が複数報告されている。
- 上限到達後: 他モデルへ切替/翌週リセットを待つ/**任意で**クレジット継続。自動課金なし。
- 残量確認: Claude Code `/usage`、claude.ai Settings > Usage。指令塔セッションからは読めないのでユーザーに尋ねる。
- API側の変化: Fable 5.1のキャッシュ読取単価が $1→$0.25/MTok。agent_usage.pyの$換算に反映済み(枠の重みへの効き方は未検証)。

## 学び
1. **lessons/006の審査観点をそのまま自分に適用した**: 効く変数はあるか→ある(Fable枠=50%上限)。失敗モードは検収と衝突するか→しない。よって型の骨格は据え置き、単位の読み替え層を1枚足すだけで済んだ。
2. **v1.0の主要施策は全て「Fable枠の温存策」として読み替え可能**: (b)構成(P2/P3=Opusメイン+Fable裁定)・配備は降板後・降板・壁打ち・束ね運転。金額ゼロになっても捨てる理由がない。
3. **緩められるのは「Fableメイン回避」の圧力だけ**: Fable残%に余裕がある週はP2でもFableメインを選んでよい(判断の質を優先)。逼迫していれば従来の(b)構成か翌週送り。
4. **「Opus/Sonnet=¥0固定費」の近似は弱まった**: 同じ週次枠を食うため、委譲先の入力トークン可視化(v0.4)は枠管理の道具として重要度が上がった。
5. **承認ゲート「クレジット投入」の意味が変わった**: Fableを使うこと自体ではなく、50%到達後にクレジット継続を選ぶこと。既定は継続しない。
6. **未較正**: $換算と`/usage`%の対応係数。セッション前後の`/usage`差分で3〜5標本 → `agent_usage.py --weekly-usd` の既定値へ。キャッシュ読取の枠重み(単価比例か)もここで検証。

## 次回どう適用するか
- 着手前: `/usage` のFable残%をユーザーに聞く → §8b判定表(v1.1の2行)で構成を決める → 枠負荷($換算)でGO/NO-GO。
- 上限到達時: クレジット継続は§7ゲート。既定は継続しない。
- 実績記帳: USD列は枠負荷($換算)。`/usage` の前後差分が取れたら備考に添えて較正標本にする。
